# 产品简报：学习守门人（暂定名）

## 一句话定位

一个安静的学习守护器：设定目标开始专注，想摸手机时通过“摩擦门”拦住你，并把每一次破功悄悄记下来，让你看到自己什么时候最容易失控。

## 问题

- 学习时注意力被手机劫持，尤其是“学了一会儿就想摸手机”
- 靠意志力对抗即时奖励不可持续，失败后容易产生挫败感

## 目标用户

- 学生与备考人群（考研、期末、考试、自学）
- 有学习意愿但自制力一般，尝试过计时/锁机工具但坚持不下来

## 现状与痛点

- 屏幕时间、Forest、番茄钟：提醒会被无视，锁机可以绕过
- 打卡/自习室：需要社交参与，单人学习场景不适用
- 物理隔离：不现实，手机在身边总有借口

## 竞品与借鉴

- Forest：仪式感与种树反馈
- one sec：打开手机前的暂停反思
- Opal：分级拦截与额度管理
- Focusmate：社会监督带来的压力感

借鉴结论：拦截要轻、反馈要即时、记录要真实。

## 差异化

- 不锁机、不吼人：安静后台运行
- 破功必须留下痕迹：想看手机要先过摩擦门并确认，数据如实记录
- 统计驱动改进：告诉用户什么时间、什么环节最容易破功

## MVP 范围

包含：

- 新建专注会话：填写目标（可选）+ 时长
- 专注计时界面
- 破功摩擦门：想中断必须点击并确认，记录破功时间
- 会话结果：专注时长、破功次数、完成情况
- 每日/每周统计：破功热区（时间段）
- 本地存储，无需账号

不包含：

- 系统级锁机与应用拦截（网页版做不到，App 阶段再做）
- 账号、云同步、多设备
- AI 对话教练与 LLM 报告
- 社交、打卡群、排行榜

## 发布形态

- 第一阶段：网页版 MVP（PWA，静态部署）
- 第二阶段：手机 App（Android 可做系统级拦截；iOS 受系统限制）

## 技术可行性

- 前端：可行，Vite + React，本地存储 + 图表，MVP 规模小
- 后端：MVP 不需要；需要同步时再加轻量后端
- AI：MVP 用规则统计；后续可加 LLM 洞察/周报
- 部署：静态托管（Vercel / Netlify / GitHub Pages）
- 限制：网页无法检测手机是否被拿起，只能通过主动确认和浏览器可见性检测；真正的系统级拦截依赖原生 App
